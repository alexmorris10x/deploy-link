Your first build, end to end.

You need a Mac with full Xcode installed, Python 3.9 or newer, Tailscale on both devices, and an iOS app already signed for the target device. These prerequisites are installed separately. The native Mac companion requires macOS 14 or later and supports Apple silicon and Intel. In Xcode → Settings → Locations, select Xcode for Command Line Tools; the standalone Command Line Tools package is insufficient. Deploy Link packages and transfers the build; it does not sign it for you.

1. Connect your devices

Install Tailscale on the Mac and iPhone or iPad. Sign into your own tailnet and enable the connection. Permit only intended devices to reach this Mac. Use Tailscale HTTPS and Serve, not Funnel: the queue is meant for your private network.

The Mac must be awake and signed in while downloading. Apple provisioning rules still apply. An expired profile, unregistered device, revoked certificate, or unsupported OS can prevent installation after a successful transfer.

2. Set up the Mac companion

Download Deploy Link for Mac

The disk image is signed and notarized. Open it, drag Deploy Link into Applications, and launch the app. Use its setup control to install the bundled server. Complete any Tailscale sign-in or HTTPS setup it requests, then try setup again.

The menu-bar item shows server status and provides start/stop controls, queue opening and address copying, build publishing, and app launch-at-login settings. Closing the window leaves the menu-bar item available. The server runs separately; quitting the Mac app does not stop it.

An existing installation is detected, and server updates preserve its queue and management token. The app uses the same queue as the command-line tools.

Alternative: install from source

Get the source repository using Git, or download and extract its source ZIP. Read the installer before running it. From the extracted repository:

git clone https://github.com/alexmorris10x/deploy-link.git
cd deploy-link
bash scripts/install_ota_queue.sh

The installer places the command under ~/.local/share/deploy-link/bin/, starts a login LaunchAgent, and configures private Tailscale HTTPS port 8443 to proxy to the loopback server, preserving other services. If Tailscale requires HTTPS setup or authentication, complete that in Tailscale and rerun the installer. It prints your queue’s HTTPS address without printing its management token.

Your builds are stored in ~/.local/share/ios-ota/queue/. The server runs only on loopback port 8477 by default. It does not open a public router port.

3. Publish a signed build

In the Mac app, choose Add Build, select a signed device .app or .ipa, add a note, and publish. You can also use the command line:

"$HOME/.local/share/deploy-link/bin/ota-queue" publish "/path/to/YourApp.app" --note "What changed"

A signed .ipa works too. Use a build intended for your target devices and distribution method, with a valid provisioning profile. Simulator builds and unsigned apps will not install. Publishing keeps the newest build of each app by default (--keep N retains more) and removes expired releases; it is not a backup of your build archive.

4. Open your queue

Copy the queue’s HTTPS address from the Mac app, or use the address printed by the source installer. Open it in Safari on your Tailscale-connected iPhone or iPad. In the Deploy Link app, when available, enter that same address in Settings, including :8443 for the default configuration. There is no shared default server or Deploy Link account.

Choose Install and confirm the system prompt. Keep the Mac online until the transfer finishes. A Downloaded label records the completed transfer, not installation success. Open the target app afterward to verify it installed.

Optional: allow queue management

Browsing and downloading do not require the management token. To let the iOS app delete queued builds, copy the server’s token locally on the Mac:

"$HOME/.local/share/deploy-link/bin/ota-queue" admin-token --copy

Paste it into the app’s management-token setting through a private transfer method. Keep it out of URLs, screenshots, issues, and shared clipboard history. Clear the clipboard after transfer. Removing a queued build deletes its server copy; it does not uninstall it from devices.

Update, stop, or remove

To update the native app, replace it in Applications with the newer download. The separately installed server is preserved. To update the server, get the current source and rerun the installer; this preserves the queue and management token.

Use the Mac app’s server control to stop or start the queue. The app has separate Launch Deploy Link at login and Start the queue at login settings. The server runs as its own login LaunchAgent. To stop the default server from Terminal without removing builds:

launchctl bootout "gui/$(id -u)/com.10x.deploy-link-ota"

Turn off the companion’s launch-at-login setting before removing the Mac app. To prevent the server returning at login, remove ~/Library/LaunchAgents/com.10x.deploy-link-ota.plist after stopping it. Remove only this queue’s Tailscale Serve mapping; preserve any other services you host. The runtime under ~/.local/share/deploy-link/ and data under ~/.local/share/ios-ota/ can then be removed when you no longer need the builds, history, and token. Custom paths need the corresponding changes.

Deleting the iOS app does not delete server records. See what is stored, or get help.
